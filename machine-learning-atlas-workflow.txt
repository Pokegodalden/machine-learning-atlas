A. ORIGINAL 14-STEP WORKFLOW WITH CURRENT STATUS
======================================================================

1. Define the app’s learning experience (Done)

   CURRENT STATUS
   Completed: Product specification, intended audience, Explore/Experiment/Compare,
   Beginner/Advanced levels, learning loop, and the 3Blue1Brown-inspired direction.
   Evidence: step-01-product-specification.md; step-01-style-reference.png.

   PLANNED WORK

   Establish three main activities: Explore, Experiment, and Compare. Explore explains algorithms; Experiment lets users change data and parameters; Compare shows how different models behave on the same problem.

   Support two explanation levels: Beginner, with plain-language descriptions, and Advanced, with equations, assumptions, and implementation details.

   Deliverable: A feature specification and a clear description of the intended audience.

2. Create the algorithm taxonomy and catalog (Done)

   CURRENT STATUS
   Completed: Structured catalog of 80 entries across 22 families and five learning
   types, explanations, parameter metadata, search indexes, schemas, and references.
   Evidence: step-02-catalog-guide.md; app-data/catalog.json; app-data/taxonomy.json.

   PLANNED WORK

   Organize the catalog using the learning types already discussed: supervised, unsupervised, semi-supervised, self-supervised, and reinforcement learning.

   Give every entry multiple tags for model family, task, and data type. Keep architectures, such as transformers, distinguishable from training algorithms and learning approaches.

   Each entry should contain a name, description, intuition, supported tasks, assumptions, strengths, limitations, parameters, example, and source references.

   Deliverable: A structured catalog that drives navigation, search, and algorithm pages.

3. Choose the first set of interactive demonstrations (Done)

   CURRENT STATUS
   Completed: Ten starter lessons selected and sequenced, seven frozen input
   fixtures, lesson storyboards, parameter specifications, and acceptance checks.
   This marks the demonstration plan complete; lesson implementation is tracked below.
   Evidence: step-03-demonstration-plan.md; app-data/demonstration-plan.json.

   PLANNED WORK

   Start with a manageable set that illustrates different behaviors: linear regression, logistic regression, a decision tree, random forest, K-nearest neighbors, a support vector machine, K-means, PCA, a small neural network, and Q-learning.

   Include explanatory catalog entries for the wider range of algorithms from the beginning. Expand runnable demonstrations in later releases, using a repeatable template for each addition.

   Deliverable: A release checklist identifying which entries have explanations, runnable demonstrations, or both.

4. Design the screens and navigation (Done)

   CURRENT STATUS
   Completed: Approved overview, algorithm detail, lesson/parameter, and comparison
   screen designs, navigation, responsive layouts, and clickable design prototype.
   Evidence: step-04-screen-design.md; design-prototype/.

   PLANNED WORK

   Create an overview page with an expandable taxonomy, searchable algorithm cards, and filters for learning type, task, and model family.

   Each algorithm page should include an explanation, a worked example, an interactive playground, and results. Add a comparison screen where users select compatible algorithms for the same task.

   Use consistent colors and labels across the taxonomy, charts, and controls.

   Deliverable: Screen mockups covering the main user journey from discovery to experimentation.

5. Define the application architecture (Done)

   CURRENT STATUS
   Completed: Modular browser app, SVG rendering, routing, content loader, worker
   execution, versioned contracts, run state, storage, build, and local server.
   Evidence: step-05-application-architecture.md; atlas-app/src/.

   PLANNED WORK

   Separate the interface, algorithm catalog, experiment engine, and results visualization.

   Use a consistent experiment contract: dataset, preprocessing choices, algorithm, parameters, random seed, and evaluation settings go in; predictions, metrics, training history, and visualization data come out.

   Lightweight demonstrations can run locally. More demanding experiments can use a backend with progress updates and cancellation.

   Deliverable: An architecture diagram and a shared input/output specification.

6. Build dataset selection and preprocessing (Done)

   CURRENT STATUS
   (Done) Seven frozen fixtures cover the selected tasks and environment.
   (Done) Supported classification lessons offer dataset selection.
   (Done) K-means fits all 240 declared unlabeled rows with comparable raw units;
   reference metadata is excluded from its worker fitting input.
   (Done) PCA centers all 200 unlabeled fit rows without standardization or
   generator-parameter leakage.
   (Done) Implemented classifiers fit scaling using training rows only.
   (Done) Shared classification panel: generated blobs/moons, sample count, noise,
   separation, outliers, stretch, data seed, feature selection, and raw/train-only
   scaling. Recipes preserve revisions through save, reopen, and exports.
   (Done) Regression recipe: samples, generating slope/intercept, noise, response
   outliers, and seed with training-only fitting and reserved final-check rows.
   (Done) Unlabeled K-means/PCA recipes: samples, shape/spread, rotation, stretch,
   outliers, seed and selected features; raw clustering and centered PCA previews.
   (Done) Generated recipes save/reopen/recompute and export with exact revisions.
   (Done) CSV column/target mapping and task compatibility; numeric median/binary mode
   imputation and category vocabulary fit only on training rows for supervised tasks.
   (Done) Reproducible splits, embedded portable source, mapped previews, real worker
   fits, source revisions, current-result exports and adaptive regression ranges.
   Scope: 80–400 records, 256 KiB UTF-8 CSV, 2–12 columns, one regression input or one/two
   other inputs. General multicategory/higher-dimensional data is expansion work.

   PLANNED WORK

   Provide small example datasets for classification, regression, clustering, dimensionality reduction, and reinforcement learning.

   Let users adjust synthetic data properties such as sample count, noise, class separation, outliers, and cluster shape. Add CSV upload after the built-in examples work reliably.

   Provide task-appropriate preprocessing controls, including feature selection, scaling, missing-value handling, and categorical encoding. Fit learned preprocessing on training data to prevent leakage into evaluation.

   Deliverable: A reusable dataset panel with a preview and clear validation messages.

7. Add model customization using dials, sliders, and numeric controls (Done)

   CURRENT STATUS
   (Done) Reusable sliders, stepped integer controls, logarithmic controls, dials,
   selectors, toggles, numeric inputs, range validation, and keyboard alternatives.
   (Done) Reset defaults and saved lesson setup loading; current/stale result states.
   (Done) Working controls for ten interactive lessons and independent comparison
   panels, with threshold-only prediction updates separated from training changes.
   (Done) K-means cluster count, Advanced restarts, and initialization selection.
   (Done) PCA component count, Advanced whitening, and centering/direction views.
   (Done) MLP depth, width, learning rate, epochs, batch size, and a combined work limit.
   (Done) Q-learning alpha/gamma sliders, epsilon dial, numeric alternatives,
   episode budget, and presentation-only recorded trajectory controls.
   (Done) CSV-dependent input/task constraints and regression coefficient ranges.
   (Done) Restore previous parameter settings in all ten lessons and independently
   in both comparison panels; Reset and quick setup Load are undoable. Numeric editing
   sessions, slider drags, held keys and dial drags are grouped into complete changes.
   (Done) Per-context history is capped at 20, resets on data/model/protocol changes
   or saved experiment opening/reload, and validates snapshots before restoring.
   (Done) Training changes cancel incompatible workers; compatible retained fits
   may be reused. Threshold-only restoration keeps fitted scores/probabilities.
   Scope complete for the starter model controls and bounded input constraints.

   PLANNED WORK

   Build a parameter panel beside the visualization. Every control should show its name, current value, default, allowed range, and a short explanation of its effect.

   Use sliders for continuous quantities, stepped sliders for integers, dropdowns for discrete choices, and dials where a compact visual control helps. Always provide keyboard operation and an editable numeric value.

   Example controls:

   - Linear/ridge regression: Regularization strength, intercept. Controls: Logarithmic slider, toggle.
   - Logistic regression: Regularization, decision threshold. Controls: Logarithmic slider, slider from 0–1.
   - Decision tree: Maximum depth, minimum samples per leaf. Controls: Integer sliders; “unlimited” option.
   - Random forest: Number of trees, depth, features considered. Controls: Integer sliders, dropdown.
   - K-nearest neighbors: Neighbor count, distance metric, weighting. Controls: Integer slider, dropdowns.
   - Support vector machine: C, kernel, gamma. Controls: Logarithmic sliders, dropdown.
   - K-means: Number of clusters, initialization, restarts. Controls: Integer sliders, dropdown.
   - PCA: Number of components. Controls: Integer slider limited by dataset dimensions.
   - Neural network: Layers, units, learning rate, batch size, epochs. Controls: Layer editor, sliders, dropdown.
   - Q-learning: Learning rate, discount factor, exploration rate. Controls: Dials/sliders with numeric inputs.

   Separate training parameters from prediction controls. Changing tree depth requires retraining; changing a classification threshold can update results using existing probabilities.

   Include Reset defaults, Restore previous settings, and Save preset. Mark results as outdated when training parameters change, and use a clear Run experiment action.

   Deliverable: A reusable parameter system with validation and algorithm-specific control definitions.

   CURRENT STATUS
   (Done) Worker pipeline, request validation, reproducible fixtures, real metrics,

   (Done) Working linear regression, kNN, logistic regression, tree, forest, SVM, K-means, PCA, MLP, and Q-learning adapters.
   (Done) All ten starter adapters include model-specific validation and bounded
   computation. Iterative learners report actual progress and support cancellation.
   Scope complete for all ten runnable starter algorithms. Reusable tooling for

   PLANNED WORK

   Connect the controls to working model implementations. Each run should validate inputs, prepare data, train the model, evaluate it, and return results.

   Show progress for longer runs and provide cancellation. Store the configuration with every result so users can reproduce it. Apply sensible computation limits and explain those limits in the interface when relevant.

   Fixed seeds should make demonstrations repeatable where supported.

   Deliverable: An end-to-end experiment pipeline used by every runnable algorithm.

   Explain that performance on one example dataset does not establish a universally best algorithm.

   Deliverable: A comparison screen that helps users understand tradeoffs.
